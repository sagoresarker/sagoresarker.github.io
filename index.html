Selected work

runbox

since Aug 2026

Go · Docker · PostgreSQL

The hosted sandbox worker behind runtimelab. It executes submitted code on my own hardware on the assumption that the code is hostile: no database credentials, no repository access, no user secrets anywhere in the blast radius. Every job runs in a container with no network and hard limits on CPU, memory, process count and wall-clock time.

The hard part: a lease with a timeout is not a lock. A worker that is paused by GC, by CPU starvation, by a partition, is not dead, and will happily finish a job another worker has already taken. Jobs are claimed under a monotonic fencing epoch that Postgres enforces on every write, so a stale worker's writes affect zero rows instead of corrupting the run.

gatecraft

since Mar 2026

Go · PostgreSQL · Redis · TimescaleDB

Five cooperating Go services (API, reverse proxy, authoritative DNS, uptime monitor, worker) covering what a small site actually needs from a web infrastructure provider. The proxy runs a full WAF (Coraza with the OWASP core rules), GeoIP blocking, Redis Lua sliding-window rate limiting and automatic Let's Encrypt certificates through CertMagic.

The hard part: the DNS server is written from the wire format up, in pure Go, with DNSSEC signing on ECDSA P-256, chosen over RSA because the signatures still fit a UDP response. Three-tier caching and response rate limiting to blunt amplification.

pgfleet

since Jun 2026

Go · Next.js · pgBackRest · PgCat

A self-hosted PostgreSQL control plane, roughly an open-source RDS. It provisions isolated container-based Postgres instances through the Docker Engine API, with a Go backend on chi and pgx and a management console. High availability through streaming replicas with read/write routing via PgCat. Written test-first, 78% coverage.

The hard part: point-in-time recovery is only real if the WAL chain is unbroken, so backups are scheduled to S3 or MinIO through pgBackRest and verified. A restore you have never tested is not a backup.

runtimelab

since Jul 2026

Go · Next.js · PostgreSQL · Docker

A self-hostable "build your own X" platform: 464 staged challenges across 5 languages. The Go backend does GitHub OAuth, hashed sessions, per-user runner tokens, long-poll job dispatch, SSE log streaming and git smart-HTTP hosting with push-to-test.

The hard part: execution works like a GitLab runner: an agent on the learner's own machine polls for jobs and runs them in Docker against checksum-pinned test suites. The server never executes untrusted code, and hosting cost stays flat as usage grows.

Earlier work on GitHub: a Memcached operator built with Kubebuilder, a finite-state-machine task queue, a sliding-window rate limiter in Redis.
