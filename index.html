Runfix

founder, since Oct 2026

Go · Temporal · PostgreSQL · ClickHouse · Cloudflare Workers · eBPF · Next.js

The safety net for apps built with AI. Founders who ship with Lovable, Bolt, Cursor or Claude Code cannot always read the code they shipped; Runfix watches their errors and deploys, guards cloud and AI spend, and when production breaks it reproduces the failure in a sandbox, writes a fix, and opens a pull request. It never merges or deploys on its own; every change is a reversible plan a human approves.

The hard part: a fix from a model is a guess until something proves it. Every candidate fix must come with a test that fails before the change and passes after, then clear fail-closed gates for regression, security and replay before a pull request exists. The heal loop runs as versioned Temporal workflows that must replay every recorded history, tenants are separated by forced row-level security in Postgres, and sandboxes get either no network or a proxy that installs exactly what the lockfile says.

incident-mind

since Aug 2026

Go · Kubernetes · Prometheus · Loki · Datadog · ArgoCD · Helm

A root-cause analysis engine for SRE and platform teams that runs inside your own cloud and only ever reads your telemetry. It takes an alert from Alertmanager or PagerDuty, gathers evidence from Prometheus, Loki, Datadog, ArgoCD and the Kubernetes API, and reports a cause with every claim tied to the evidence behind it. Ships as a Helm chart with read-only RBAC and a single-egress network policy.

The hard part: keeping the model honest. A deterministic state machine in Go owns the investigation and the evidence graph; the language model only proposes, and every hypothesis has to say what result would disprove it. Recent changes are ranked by timing and dependency distance before any model call, raw telemetry never enters a prompt, and an investigation replays byte for byte.

runbox

since Aug 2026

Go · Docker · PostgreSQL

The hosted sandbox worker behind runtimelab. It executes submitted code on my own hardware on the assumption that the code is hostile: no database credentials, no repository access, no user secrets anywhere in the blast radius. Every job runs in a container with no network and hard limits on CPU, memory, process count and wall-clock time.

The hard part: a lease with a timeout is not a lock. A worker that is paused by GC, by CPU starvation, by a partition, is not dead, and will happily finish a job another worker has already taken. Jobs are claimed under a monotonic fencing epoch that Postgres enforces on every write, so a stale worker's writes affect zero rows instead of corrupting the run.

gatecraft

since Mar 2026

Go · PostgreSQL · Redis · TimescaleDB · Temporal

Five cooperating Go services (API, reverse proxy, authoritative DNS, uptime monitor, worker) covering what a small site actually needs from a web infrastructure provider. The proxy runs a full WAF (Coraza with the OWASP core rules), GeoIP blocking, Redis Lua sliding-window rate limiting and automatic Let's Encrypt certificates through CertMagic. The long-running work behind all of it — scheduled checks, certificate renewal — runs as Temporal workflows, so a restart resumes where it left off instead of starting the job over.

The hard part: the DNS server is written from the wire format up, in pure Go, with DNSSEC signing on ECDSA P-256, chosen over RSA because the signatures still fit a UDP response. Three-tier caching and response rate limiting to blunt amplification.

pgfleet

since Jun 2026

Go · Next.js · pgBackRest · PgCat

A self-hosted PostgreSQL control plane, roughly an open-source RDS. It provisions isolated container-based Postgres instances through the Docker Engine API, with a Go backend on chi and pgx and a management console. High availability through streaming replicas with read/write routing via PgCat. Written test-first, 78% coverage.

The hard part: point-in-time recovery is only real if the WAL chain is unbroken, so backups are scheduled to S3 or MinIO through pgBackRest and verified. A restore you have never tested is not a backup.

runtimelab

since Feb 2026

Go · Next.js · PostgreSQL · Docker

A self-hostable "build your own X" platform: 464 staged challenges across 5 languages. The Go backend does GitHub OAuth, hashed sessions, per-user runner tokens, long-poll job dispatch, SSE log streaming and git smart-HTTP hosting with push-to-test.

The hard part: execution works like a GitLab runner: an agent on the learner's own machine polls for jobs and runs them in Docker against checksum-pinned test suites. The server never executes untrusted code, and hosting cost stays flat as usage grows.

Earlier work on GitHub: a Memcached operator built with Kubebuilder, a finite-state-machine task queue, a sliding-window rate limiter in Redis.
