Selected work

Runfix

founder, since Oct 2026

The safety net for apps built with AI. Founders who ship with Lovable, Bolt, Cursor or Claude Code cannot always read the code they shipped; Runfix watches their errors and deploys, guards cloud and AI spend, and when production breaks it reproduces the failure in a sandbox, writes a fix, and opens a pull request. It never merges or deploys on its own; every change is a reversible plan a human approves.

The hard part: a fix from a model is a guess until something proves it. Runfix only opens a pull request when the fix comes with a test that fails before the change and passes after, and it never merges or deploys anything by itself.

incident-mind

in development, since Aug 2026

Go · Kubernetes · Prometheus · Loki · Datadog · ArgoCD · Helm

A root-cause analysis engine I'm building for SRE and platform teams. It runs inside your own cloud and only reads telemetry: given an alert from Alertmanager or PagerDuty, it gathers evidence from Prometheus, Loki, Datadog, ArgoCD and the Kubernetes API and reports a cause with every claim tied to evidence. Packaged as a Helm chart with read-only RBAC and a single-egress network policy; so far evaluated on scripted incidents, not yet on a live cluster.

The hard part: keeping the model honest. A deterministic state machine in Go owns the investigation and the evidence graph; the language model only proposes, and every hypothesis has to say what result would disprove it. Recent changes are ranked by timing and dependency distance before any model call, raw telemetry never enters a prompt, and an investigation replays byte for byte.

runbox

since Aug 2026

Go · Docker · PostgreSQL

The hosted sandbox worker behind runtimelab. It executes submitted code on my own hardware on the assumption that the code is hostile: no database credentials, no repository access, no user secrets anywhere in the blast radius. Every job runs in a container with no network and hard limits on CPU, memory, process count and wall-clock time.

The hard part: a lease with a timeout is not a lock. A worker that is paused by GC, by CPU starvation, by a partition, is not dead, and will happily finish a job another worker has already taken. Jobs are claimed under a monotonic fencing epoch that Postgres enforces on every write, so a stale worker's writes affect zero rows instead of corrupting the run.

gatecraft

since Mar 2026

Go · PostgreSQL · Redis · TimescaleDB · Temporal

Five cooperating Go services (API, reverse proxy, authoritative DNS, uptime monitor, worker) covering what a small site actually needs from a web infrastructure provider. The proxy runs a full WAF (Coraza with the OWASP core rules), GeoIP blocking, Redis Lua sliding-window rate limiting and automatic Let's Encrypt certificates through CertMagic. Domain verification, activation, alerting and retention run as Temporal workflows, so a restart resumes where it left off instead of starting the job over.

The hard part: the authoritative DNS server signs answers per query with DNSSEC on ECDSA P-256 instead of RSA, which keeps signed responses small enough to fit in UDP. It sits on miekg/dns for the wire codec, with three-tier caching and response rate limiting to blunt amplification.

pgfleet

since Jun 2026

Go · Next.js · pgBackRest · PgCat

A self-hosted PostgreSQL control plane, roughly an open-source RDS. It provisions isolated container-based Postgres instances through the Docker Engine API, with a Go backend on chi and pgx and a management console. High availability through streaming replicas with read/write routing via PgCat. Written test-first, 78% coverage.

The hard part: point-in-time recovery is only real if the WAL chain is unbroken, so backups are scheduled to S3 or MinIO through pgBackRest and verified. A restore you have never tested is not a backup.
